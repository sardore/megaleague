**이 문서를 결론으로 받아들이지 말고 독립적으로 반박 가능한 리뷰를 수행하라.**

1. 최신 \`main\` SHA와 이 문서의 기준 SHA를 비교한다. 이미 해결된 항목은 \`STALE/RESOLVED\`로 표시한다.
2. 각 항목의 파일/함수/실행 경로를 직접 읽고, **CONFIRMED BUG / CONFIRMED DOC DRIFT / DESIGN CHOICE / TEST GAP / FALSE POSITIVE / NEEDS EVIDENCE** 중 하나로 판정한다.

4. 추천하는 수정은 가능한 한 기존 공통 엔진 경로에 가하는 최소 변경으로 제한한다. 래퍼/몽키패치/새 전역 제어기 중첩, UI만 덮는 임시방편, 비결정론적 타이머 추가 금지.

6. PR에 한국어로 항목별 판정 근거(코드 경로, 테스트 명령, PASS/FAIL, 수정 최소안, 남은 불확실성)를 회신한다. 접근·빌드·테스트가 불가하면 명시한다.

## CR-01. 웰러 예약 저주 대상 정책 문서 정정 (P1, CONFIRMED DOC DRIFT)

**관찰**

- \`docs/weller-verification.md\`는 억누른저주가 대상 UID를 저장하고 교체 뒤에도 그 개체를 추적한다고 설명한다.
- \`src/features/weller.js\`의 \`applyWellerEffect\`는 \`scheduledSlotRef(g,target)\`만 예약에 넣는다.
- \`src/engine/effects.js\`의 \`executeScheduled\`는 슬롯의 **현재 점유자**를 대상으로 후속 실행하고, 빈 슬롯에서는 불발한다.
- \`tools/check-weller.js\`의 'curse is a slot reservation ...' 케이스가 교체 슬롯 계승 및 빈 슬롯 불발을 검사한다.

**검증 요청**: 실제 \`main\`에서 테스트를 실행해 현재 정책을 확정한다. 문서의 해당 문장을 슬롯 추적/빈 슬롯 불발로 수정한다. 캐릭터나 예약 로직 자체는 변경하지 않는다. UI 기술 설명에도 혼동이 있는지 확인한다.

**완료 조건**: 문서·캐릭터 설명·테스트가 동일한 정책을 설명하고 기존 테스트 PASS.

## CR-02. 웰러 그레이브업 회복 정책 문서 정정 (P1, CONFIRMED DOC DRIFT)

**관찰**

- \`docs/weller-verification.md\`는 '자기 차례 회복 4회' 및 사실상 고정 40씩 회복하는 이전 구현을 설명한다.
- 현재 \`src/features/weller.js\`는 \`graveUpRecovery\` 카운터 대신 \`addHpProtectionBarrier(..., { decayPerTurn:40, healOnDecay:'graveUp' })\`를 사용한다.
- \`src/engine/effects.js\`의 \`decayHpProtectionBarriers\`는 실제로 자연 감소한 보호막 수치만큼 \`heal\`을 호출한다.
- \`tools/check-weller.js\`에는 받은 피해 때문에 보호막이 줄었다면 그 피해분을 회복하지 않는 테스트가 있다.

**검증 요청**: (A) 무피해 보호막 160→120에서 40 회복, (B) 피격으로 남은 보호막 30→0에서 30만 회복, (C) 먼저 전부 소진된 보호막은 환급 0, (D) 중복 차례 준비와 복원에서 중복 회복 없음. 현재 코드의 기대대로 테스트된 후 문서를 업데이트한다.

**완료 조건**: 설명이 보호막 자연 감소 기반임을 명시, 고정 회복으로 오독하지 않음.

## CR-03. 일반 실드 / HP 보호막 / 실드멜트 피해 규칙 회귀 테스트 (P1, DESIGN CHOICE + TEST GAP 후보)

**관찰**

- \`src/engine/combat.js\`의 \`applyResolvedDamagePacket\`: 일반 \`target.shield > 0\`에서 \`shieldMelt\`가 아니면 공격 피해가 실드 초과분을 본체 HP로 이월하지 않는다.
- \`applyHpPortion\`/ \`absorbHpProtectionBarrier\`는 HP 보호막의 초과분을 본체 HP에 적용한다.
- \`dealDamage\`는 다단 공격의 각 타격을 순차 처리하므로 소량 일반 실드의 효율이 단발 공격과 크게 달라질 수 있다.

**정확히 고정할 사례**: 기본 방어·반사·회피·변동·특성 없음, 최종 공격 패킷 160D, 본체 HP 240.
- 일반 실드 1, \`shieldMelt=false\`: 실드 0, HP 240 예상.
- HP 보호막 1, 일반 실드 0: HP 81 예상(초과 159).
- 일반 실드 1, \`shieldMelt=true\`: HP 81 예상.
- 80D 2타, 일반 실드 1: 1타에는 HP 피해 0, 다음 타격은 HP에 80(다른 효과 없을 때) 예상.

**검증 요청**: 게임 디자인상 의도인지 먼저 확인한 후 계약 테스트 작성. 의도된 규칙이면 변경하지 않는다. 로그·통계 \`DAMAGE_APPLIED\`·실드/HP 감소 수치도 일치 여부를 검사한다.

## CR-04. 타임오러의 전역 특성 정지 반응 (P1, INTERACTION TEST)

**관찰**

- \`src/features/timeora.js\`의 \`TimeClockTraitSuppressionPolicy.resolve\`는 정렬된 시계 주인 UID를 제외한 **양 진영 필드 유닛**의 특성을 정지 대상으로 취급한다.
- 양쪽에 정렬된 시계 주인이 존재하면 두 효과가 상쇄된다.
- \`src/engine/combat.js\`의 \`combatStats\`와 \`traitsActive\` 경로가 타임오러 방어 오라, 이루마 경감, 호리진탈 팀 경감 등에 영향.

**검증 사례**:
1. 타임오러 한쪽만 정렬: 적 이루마 피해경감과 같은 편 호리진탈 팀 경감 모두 정지하는 것이 설계 의도인지.
2. 양 진영 타임오러 동시 정렬: 정지 상쇄와 하이퍼클락 강화가 독립적으로 적용되는지.
3. 특성봉인 및 직전 적 행동에서 시계 회전 금지, 반에너지 소비 시 회전량의 반올림 처리.
4. 온라인 권위 상태/클라이언트 연출에 정지 대상과 피해 계산이 일치하는지.

**완료 조건**: 시계 중복·상쇄와 턴 경계에 관한 동일 시드의 결정론적 실행 테스트. 밸런스 너프는 별도 검토.

## CR-05. 타임리콜의 상태 복원 및 회복 통계 계약 (P1, CONTRACT TEST)

**관찰**

- \`src/features/timeora.js\`의 \`timeApplyRecall\`: 과거 HP, 상태이상, 기술봉인 상태를 **스냅샷 대입**으로 복원한다.
- 실드, HP 보호막, 에너지, 최대 HP는 현재 상태를 유지한다.
- HP가 늘면 통계에 회복으로 기록하지만 일반 \`heal\` 경로 자체는 사용하지 않는다.
- \`statusAppliedTurnSerial\`은 복원된 언데드에 대해 현재 \`turnSerial\`로 재설정된다.

**검증 요청**:
- 회복봉인·언데드·이루마의 즉시 치료·특성 정지 상태에서 복원 결과가 설계 의도에 맞는지.
- 동일 스냅샷의 재적용 방지(1회 사용권), HP 0과 사망 판정, 보유 자원/방어막 보존.
- \`healing\` 통계와 실제 HP 증가량의 일치 및 네트워크 복원 후 기록 중복 여부.
- 스냅샷 이력이 0~2개인 초기 차례에서 되감기 기준 확인.

**완료 조건**: 되감기는 '일반 회복'과 다를 수 있다는 규칙을 명시하고 케이스별 테스트 통과. 의도 확인 전 \`heal\` 호출로 교체하지 말 것.

## CR-06. 예약 공격 재접속/중복 처리 불변식 (P1, NETWORK/ENGINE TEST)

**관찰**

- \`src/engine/effects.js\`: \`ensureScheduledActionIdentity\`, \`beginScheduledActionExecution\`, \`completeScheduledActionExecution\`, \`executeScheduled\`가 예약 ID 및 실행 완료 ID로 중복 적용을 방지한다.
- \`src/engine/execution.js\`: 예약 행동은 완료/중복 처리 후 턴을 진행한다.
- 과거 멀티플레이 문제를 고려하면, 행동 직전/직후 스냅샷과 재접속 시 실행 여부가 중요하다.

**검증 요청**:
1. 예약 확정→같은 명령 재전송→처음 한 번만 효과 적용.
2. 예약 실행 전/후 각각 스냅샷 복구→HP/에너지/예약 ID/턴 일치.
3. 예약 목표 슬롯 교체/빈 슬롯→웰러와 일반 예약기의 정책 일관성 확인.
4. 2클라이언트에서 권위 revision, 시각 이벤트 ID 및 상태 수렴 확인.
5. 실패·예외 경계 시 턴 중복 증가/양측 대기 고착이 재발하지 않는지.

**완료 조건**: 두 독립 클라이언트의 공통 상태 해시, 턴 직렬번호, 재전송 시 피해 적용 횟수 일치. 기존 세션 권한 경계를 재구조화하지 말고 재현되는 최소 분기만 수정.

## CR-07. 반 에너지와 비용 변환 테스트 강화 (P2, RULE CONSISTENCY)

**관찰**

- \`src/engine/energy.js\`는 R/W/B별 수량과 0.5E 단위를 지원하며, \`transformedSkillReq\`는 독 추가 코스트 및 필드 변환을 반영한다.
- \`src/features/timeora.js\`의 시간 가속은 기본 1E+보너스 0.5E, 재추첨, 보관 한도 초과 시 교환 분기를 가진다.
- UI의 결제 계획·자동 선택과 서버 실행이 어긋나지 않는지가 중요하다.

**검증 요청**: 다양한 색 배열, 감속 상태 0.5E, 독 중첩, 가득 찬 4E 상태, 재추첨/보너스 보류, 결제 계획 유효성·에너지 보존, 같은 RNG 시드의 예측/실행 일치. 특정 캐릭터의 비용 패치를 통한 우회는 피한다.

## CR-08. 필수 전투 불변식 테스트의 빠른 CI 분리 (P2, MAINTAINABILITY)

\`package.json\`의 \`npm test\`는 \`tests/unit/*.test.js\`만 실행한다. \`tools/check-weller.js\`와 \`tools/check-combat-online.js\`는 별도 명령이다. CI 구성이 실제로 무엇을 실행하는지는 각 워크플로를 다시 확인한다.

**제안**: 룰/캐릭터/예약 엔진 파일 변경 PR에는 빌드 + 정적 검사 + 단위 검사 + 대표 전투 회귀를 실행하는 명시적인 빠른 경로를 검토한다. 브라우저/릴레이 E2E를 무조건 모든 커밋에 추가하기보다는 기존 게이트와 역할을 구분한다. 새 CI 워크플로 필요 여부는 Claude의 비용/소요시간/기존 게이트 조사 후 판단한다.
